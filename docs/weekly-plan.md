# 주간 계획 설계서

작성 2026-09-27 (grill 합의). `docs/claude-connector-plan.md`의 "오늘 루틴 1개" 방식을 **한 주 계획**으로 바꾼다.
커넥터 설계서의 결정 1~5·7~14는 그대로이고, **결정 6의 "주간 계획·분할 제안 안 함"은 이 문서가 대체한다.**

## 근거
- ACSM 2026 입장문(Currier 외, *MSSE* 58(4):851-872, PMID 41843416, 137개 리뷰·3만 명+):
  근비대는 **부위당 주 10세트 이상**에서 향상(용량-반응, 약 18~20세트부터 수확 체감). 모든 큰 근육 **주 2회 이상**.
  볼륨이 같으면 빈도(주 1회~5회+)·주기화·실패 여부는 근비대에 일관된 차이 없음. 실패 대신 2~3 RIR이면 충분.
- 분할 방식 자체는 근비대에 차이 없음(`docs/research/training-splits.md`) → 순서를 사용자가 고르게 두어도 된다.

## 결정 (사용자 확정)
1. 월요일에 Claude(Opus)가 한 주 전체를 숫자까지(종목·세트별 무게·반복·워밍업·휴식) 저장한다. 앱은 그대로 실행한다.
2. 분할 고정: 3일 = 전신 A·B·C / 4일 = 상체 A·하체 A·상체 B·하체 B / 5일 = PUSH·PULL·하체 A·상체·하체 B.
3. 주 일수(3·4·5)는 Claude 대화에서 말한다. 말하지 않으면 Claude가 묻는다. 앱에 설정 화면 없음.
4. 운동 탭: 이번 주 남은 세션 카드. 지난번 세션과 주동 부위가 겹치지 않는 세션을 맨 위로(막지는 않음). 끝난 세션은 ✓와 요일로 아래에. 맨 아래 「기본 루틴」 한 줄 → 기존 부위 카드.
5. 주 중 수정: 안 한 세션은 몇 개든 Claude가 고친다(추가·삭제 포함). 끝난 세션은 바꿀 수 없다. 고칠 때 이번 주 부위별 세트를 다시 맞춘다.
6. 한 주 = 월~일(KST). 일요일에 저장한 계획은 다음 주 것. 일요일이 지나면 못 한 세션은 사라진다. 계획이 없으면 기본 부위 카드.
7. 기록 탭 「부위별 주간 볼륨(2주 평균)」 카드 → 「이번 주 부위별 세트」(Claude 목표 / 실제). 계획이 없으면 실제만.
8. 앱의 5주 사이클(빌드 4 + 디로드 1)과 주 목표 횟수 설정을 통째로 삭제. 홈 맨 위는 「이번 주 계획」 카드(n일 중 m일·남은 세션·디로드 표시·오래 쉰 뒤 안내).
9. 유산소는 지금처럼 그날그날(`save_today_cardio` 유지).
10. 안내문의 세트 기준은 바닥선만: "부위마다 주 10세트 이상, 주 2회 이상". 그 위는 Claude가 정한다.
11. ACSM 2026에서 앱에 반영(사용자 요청): 안내문 「사용자가 따르는 근거」 절 — 종목당 본 세트 2세트 이상, 실패 불필요(여유 2~3회 기본),
    무거운 복합 종목 앞쪽·가동범위 끝까지·내리는 동작 조절, 볼륨이 같으면 빈도·주기화·세트법·속도·순서 차이 없음(→ 5주 사이클 삭제와 같은 근거).
    넣지 않은 것: 18~20세트 수확 체감선(사용자가 바닥선만 고름), 세트 사이 휴식(근비대 근거 부족), 기본 루틴 엔진 값(이미 범위 안 — 종목당 3세트, 마지막 세트 여유 0~1회).
12. (v72, 사용자 요청) 다음 주 계획이 저장돼 있으면 홈 「이번 주 계획」 카드 맨 아래에 `다음 주 계획 준비됨 · N일` 한 줄. `/api/plan`이 `nextWeek`도 준다. 운동 탭에는 넣지 않는다.
13. (v72) 스냅샷 날짜는 앱이 `YYYY-MM-DD`로 맞춰 보낸다(한 자리 월·일은 채우고, 망가진 날짜 항목만 뺀다) — 한 건 때문에 업로드 전체가 조용히 실패하던 기존 결함.

## 기본값 (확정 때 함께 승인)
- 세션 ✓ = 그 세션으로 시작해 저장한 운동이 있음(일부만 해도).
- 앱에서 손으로 고친 내용은 그 세션에 남는다. Claude가 그 세션을 다시 저장하면 Claude 것으로 바뀐다. 이미 시작한 운동에는 반영하지 않는다.
- `save_today_routine`은 없애고 주간 도구로 대체. 계획 밖 하루는 Claude가 세션을 추가한다.
- 주 중간에 처음 계획해도 그 주 계획이다.
- 세트 세기: 본 세트만(워밍업 제외), 종목의 주동 부위 1 · 보조 부위 0.5. 앱 카드와 Claude가 **같은 무게표**로 센다.
- 세션 시간 70분 안팎 유지.

## 데이터 계약
`WeekPlan = {id, createdAt, updatedAt, weekStart:'YYYY-MM-DD'(월요일), days:3|4|5, deload:bool, note,
  targets:{<부위 그룹 키>: 세트 수}, sessions:[{label, type, note, updatedAt, exercises:[{name, note, sets:[{weight, reps, warmup, restSec}]}]}]}`
- `type` ∈ `full|upper|lower|push|pull` → 종목 목록: full=free, lower=legs, 나머지 같은 이름.
- `label`은 그 주 안에서 유일하고 세션의 이름표다(예: `상체 A`). 운동 기록에 `planWeek`(weekStart)·`planLabel`을 남겨 ✓를 판정한다.
- 부위 그룹 키 = `BODY_PART_GROUPS` 14개(chest, shoulders_front, shoulders_side, shoulders_rear, triceps, lats, upper_back, biceps, quads, hamstrings, glutes, adductors, calves, abs).
- 저장소 키 `fitness/week/<weekStart>.json`(주마다 따로 — 일요일에 다음 주를 저장해도 이번 주 일요일 세션이 남는다). 유산소 키는 그대로.

## MCP 도구
1. `get_training_context` — 지금 절들 + 「이번 주 계획」(세션별 ✓/남음, 목표) + 「다음 주 계획」(있으면) + 「이번 주 부위별 실제 세트」 + 종목 목록에 종목별 부위 무게표.
2. `save_week_plan` — 한 주 저장. `week?: this|next`(없으면 일요일=next, 그 밖=this). 그 주에 끝난 세션이 있으면 서버가 그대로 두고, 입력에 같은 label이 있으면 저장하지 않고 알려 준다.
3. `update_week_sessions` — `week?`, `upsert[]`(label 기준 교체·추가), `remove[]`(label), `targets?`, `note?`, `deload?`. 끝난 세션을 건드리면 저장하지 않는다.
4. `save_today_cardio` — 그대로.
5. `get_saved_plans` — 이번 주·다음 주 계획 + 오늘 유산소.
- 끝난 세션 판정(서버) = 최신 스냅샷 운동 기록의 `planWeek`·`planLabel`. 앱은 자기 기록으로 판정한다.
- 종목 이름 검사는 세션 `type`의 목록 기준. 틀리면 비슷한 이름을 돌려준다(지금과 같음).

## 앱
- `/api/plan` → `{week, nextWeek, cardio}`(week = 오늘이 속한 주의 계획, nextWeek = 다음 주 계획). 앱은 `state.weekPlan`·`state.nextWeekPlan`에 두고 기기 저장(백업 제외).
- 운동 저장 시 `planWeek`·`planLabel` 기록. 스냅샷 운동 항목에 두 필드 + `muscleWeights{종목: {그룹: 1|0.5}}`.
- 부위별 세트 계산은 앱 함수 하나(`exerciseGroupWeights`)가 정본. 카드·스냅샷이 모두 이것을 쓴다. 서버는 스냅샷의 무게표로 같은 합을 낸다.
- 겹침 규칙(정렬용): push={가슴,어깨 전면·측면,삼두}, pull={광배,등 중부,이두,어깨 후면}, upper=push∪pull, lower={사두,햄,둔근,내전근,종아리}, full=전부. 기본 루틴 세션도 같은 표(legs=lower, free=full).
