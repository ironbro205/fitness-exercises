# 헬스앱 세트 운영방식 재조사 v2 — 전수 카탈로그 · 탑세트 구조 판정 · 앱 반영 설계

## 0) 한 장 요약 — 결론부터

### 0-A. 사용자가 제기한 두 가지에 대한 답

**① "탑세트는 웜업 → 피더 → 탑 → 백다운 70% 아니냐"**

→ **용어는 맞고, 숫자 하나가 서로 어긋난다.** 사용자가 아는 구조는 한국·해외 보디빌딩계의 표준 용어법이 맞다(워밍업/피더/탑/백다운 4단계는 John Meadows 계열에서 널리 쓰인다). 하지만 **"70% 무게"와 "최대 15회"는 서로 짝이 맞지 않는다.**

부하–반복 관계 메타회귀(Nuzzo 2023, 269연구·7,289명)로 계산하면:

| 탑세트가 | 백다운 70% 의 실제 1RM % | 그 무게의 **한계 반복** | 15회에서 끊으면 |
|---|---|---|---|
| 8회짜리(≈80% 1RM) | 56% 1RM | 약 21~23회 (피로 후 ~18회) | RIR 3 — 아슬아슬하게 허용 |
| **10~12회짜리(≈73~75% 1RM)** | **52% 1RM** | **약 24~27회 (피로 후 ~20회)** | **RIR 5~6 — 자극 미달** |

Refalo 2023 메타는 **실패에서 4~5회 이상 남기면 근비대가 뚜렷하게 떨어진다**고 보고했다. 즉 사용자 정의의 "탑세트 8~12회 + 백다운 70% + 15회 상한" 조합은 백다운 세트가 **RIR 6짜리 헛세트**가 된다.

**"12~15회를 한계 근처까지"를 실제로 성립시키는 무게는 탑세트의 80~85%다.** 70%가 아니다. 이건 취향이 아니라 산수다.

**② "피라미드·역피라미드가 왜 없냐"**

→ **1차 보고서의 '옵션으로 제공' 권고가 구현에서 누락된 게 맞다.** 넣는 게 옳다. 다만 **기본 배정은 하지 않는다** — 근거상 스트레이트와 동등하고(Angleri 2017 CSA +7.5% vs +7.6%), 2024년 급성 연구는 어센딩이 스트레이트와 아무 차이가 없다고 보고했다.

### 0-B. 이번 재조사의 새 근거 — 1차 결론을 뒤집는가?

**뒤집지 않는다. 오히려 더 강해졌다.**

| 새로 확인한 메타분석 (2025~2026) | 결과 |
|---|---|
| **Tsartsapakis 2026** — 고급 세트법 전반(레스트포즈·드롭·클러스터·템포·속도기반·이심과부하) 24연구 | **근비대 g = 0.046 [−0.057, 0.149], p = 0.370 — 유의차 없음.** 근력만 g = 0.351 (유의) |
| **Havers 2026** — 드롭세트 12연구·274명 | 근비대 SMD 0.04 [−0.29, 0.36] · 근력 SMD −0.04. 반면 **RPE SMD 1.62 · 젖산 SMD 0.67 · 신경근 피로 더 큼** |
| **클러스터 세트 2025** (EJAP, 볼륨·노력 매칭) | 제지방 CS +171.8 g vs TS +201.1 g (p = 0.272) — 동등 |
| **어센딩 vs 디센딩 피라미드 2024** (IJSC 급성) | 셋 다 볼륨 동등. **디센딩만 최대속도·RPE가 유의하게 낮음** |

→ **"세트법을 바꿔서 근육을 더 키운다"는 길은 없다.** 세트법은 *피로·시간·폼·추적 가능성*을 사는 도구다. 이 프레임을 v2에서도 유지한다.

### 0-C. 최종 권장 (한눈에)

| 항목 | 권장 | 근거등급 |
|---|---|---|
| **탑세트 구조** | **현행 골격 유지**(탑 1 + 백오프 2 @ 90%, 같은 반복). 여기에 **① 피더 세트 1개를 워밍업 램프 끝에 추가** ② **마지막 백오프만 RIR 0~1** ③ **탑세트가 목표 미달이면 백오프를 한 스텝 더 감량** | 중간 |
| **사용자 정의 구조** | `top_backdown` **신규 스킴으로 시트에 추가**. 단 백다운 무게는 **70%가 아니라 82.5%**, 목표 **12~15회 RIR 0~1**, **2세트**(볼륨 유지) | 중간 |
| **피더 세트** | **별도 개념으로 두지 않는다.** 현행 램프업 워밍업의 **마지막 단을 90% × 2~3회로 올리는 것**이 곧 피더다 | 중간 |
| **추가할 세트법 5종** | `top_backdown` · `pyramid`(어센딩) · `rpt`(역피라미드) · `cluster`(클러스터) · `rest_pause`(마이오렙에서 분리) | — |
| **기본 배정** | **바꾸지 않는다.** 근비대 차이가 0이므로 기본값을 흔들 근거가 없다 | 높음 |
| **GVT(10×10)** | **채택 안 함.** 10세트가 5세트보다 낫지 않았고, 몸통·팔 제지방은 **5세트가 우세**했다(Amirthalingam 2017) | 중간 |

## 1) 세트법 전수 카탈로그 + 정밀 처방표

### 1-0. 표기 규칙

| 기호 | 뜻 | 앱에서 나오는 곳 |
|---|---|---|
| **W** | 오늘의 추천 워킹 무게 | `getProgressiveRecommendation(name, reps).weight` |
| **R.low / R.high** | 클래스 반복 범위 하단·상단 | `clampRepsToClass(name, reps)` |
| **step** | 그 장비의 최소 증량 단위(덤벨 2kg, 그 외 5kg) | `getWeightIncrement(name)` |
| **RIR** | 그 세트에서 더 할 수 있었던 반복 수. RIR 0 = 실패 | — |

**근거등급 정의** (이 문서 전체에서 동일)

| 등급 | 뜻 |
|---|---|
| **높음** | 메타분석 2편 이상 또는 메타분석 + RCT 다수가 같은 방향 |
| **중간** | RCT 1~2편, 또는 급성 연구 + 체계적 고찰 |
| **낮음(실무)** | 코치·기관 권장 합의. 원리는 근거가 있으나 **정확한 숫자는 임의** |
| **없음** | 직접 연구 없음. 논리적 추론만 |

**부하–반복 환산표** (아래 모든 계산의 기준 — Nuzzo 2023, *Sports Medicine*, 269연구·7,289명·952회 실패반복 검사)

| %1RM | 벤치 프레스 (평균 회) | 레그 프레스 (평균 회) | 개인차(SD) |
|---|---|---|---|
| 80% | **8.8** [7.7–10.1] | **13.1** [9.8–17.5] | ±2.5 |
| 70% | **14.1** [12.4–16.1] | **19.0** [14.2–25.5] | ±4.4 |
| 60% | ~20 | ~26 | 더 큼 |

> ⚠️ **이 표를 절대값으로 믿으면 안 된다.** 개인차 SD가 80%에서 ±2.5회, 70%에서 ±4.4회다. 하체가 상체보다 같은 %에서 4~6회 더 나온다. 아래 처방 %는 **출발점**이고, 실제 조정은 RIR 관찰로 해야 한다.
>
> **이 문서의 계산 방법**(재현 가능하도록 명시): 70~80% 구간은 위 두 점을 **선형 보간**했다(벤치 기준 1%당 약 0.53회). 60% 아래는 관계가 볼록해져 선형 외삽이 반복 수를 **과소평가**하므로, 그 구간은 폭(예: "약 24~27회")으로 적었다. 탑세트 뒤의 피로 계수는 **×0.8(범위 0.7~0.9)** 을 썼다 — Nuzzo 2024는 실패 세트 연속에서 세트2가 70%라고 보고했고, 앱은 휴식 180초 + 탑세트 RIR 1~2(실패 아님)라 그보다 완만하다고 본 값이다. **이 0.8은 추정치이며 실측이 아니다.**

### 1-A. 스트레이트 세트 (straight)

**정의**: 모든 워킹세트를 같은 무게·같은 목표 반복으로.

| 항목 | 처방 |
|---|---|
| 세트 수 | 워킹 3세트 (근거상 종목당 4~6세트가 상한 — Amirthalingam 2017) |
| 세트별 무게 | 전부 **W** |
| 세트별 목표 횟수 | 전부 **R.low ~ R.high** |
| 세트 간 휴식 | 클래스 기본값 (고중량복합 180 / 중강도복합 150 / 고립 120 / 경량고립 90 / 재활 60초) |
| RIR 목표 | 복합 2~3 · 고립 0~2 (마지막 세트 0~1) |
| 적합 종목 | **전부**. 특히 중강도 복합·고립 |
| 진행 규칙 | 더블 프로그레션 — **모든 세트가 R.high 도달** → (클래스별 1~2세션 연속) → +1 step |
| 근거등급 | **높음** — 비교 기준선 그 자체 |

**뒤 세트 반복이 떨어지는 건 정상이고 병이 아니다.** Nuzzo 2024(JSCR, 29연구 2차분석)는 고정 부하로 연속 실패 세트를 하면 **세트2가 세트1의 약 70%, 세트3이 55%, 세트4가 50%** 라고 보고했다. 휴식을 길게 하면 감소가 완화되지만 곡선 모양은 그대로다.

### 1-B. 탑세트 + 백오프 (top_backoff) — 현행 `compound_heavy` 기본

**정의**: 그날 가장 무거운 1세트(탑) → 무게를 조금 낮춰 **같은 반복 목표**로 2세트.

| 항목 | 처방 (현행 + 이번 권장 수정) |
|---|---|
| 세트 수 | 워밍업 2~**3** + 탑 1 + 백오프 2 |
| 세트별 무게 | 탑 = **W** · 백오프 = **W × 0.90** (최소 1 step 하강 보장) |
| 세트별 목표 횟수 | 탑·백오프 **모두 R.high** (예: 8회) |
| 세트 간 휴식 | 180초 (`compound_heavy`) |
| RIR 목표 | 탑 1~2 · 백오프 2~3 · **[신규] 마지막 백오프만 0~1** |
| 적합 종목 | **고중량 복합**(벤치·풀업·딥스·바벨 로우·핵 스쿼트). 프리·머신 무관 |
| 진행 규칙 | **탑세트가 R.high 달성 → 2세션 연속 → +1 step.** 백오프는 무게가 달라 판정에서 자동 제외 |
| 근거등급 | **낮음(실무 합의)** — 직접 RCT 없음. 원리(볼륨 로드 보존)만 근거 있음 |

**왜 90%(−10%)인가 — 이번에 계산으로 검증했다.**

탑세트를 8RM(≈80% 1RM) 무게 W로 잡았을 때, 백오프 배율에 따른 착지점:

| 백오프 배율 | 실제 1RM% | 한계 반복(벤치, 피로 없을 때) | **탑세트 후 실제 가능**(≈×0.8) | 목표 8회일 때 RIR |
|---|---|---|---|---|
| 1.00 (감량 없음) | 80% | 8.8 | ~7 | **−1 (못 채움)** ❌ |
| 0.95 | 76% | 10.9 | ~9 | 1 |
| **0.90 (현행)** | **72%** | **13.0** | **~10** | **2** ✅ |
| 0.85 | 68% | 15.2 | ~12 | 4 |
| 0.80 | 64% | 17.3 | ~14 | 6 ❌ 자극 미달 |
| 0.70 | 56% | ~22 | ~18 | **10** ❌❌ |

→ **같은 반복을 유지하는 구조에서는 감량폭이 작아야 맞다.** 감량을 크게 하면 RIR이 커져 자극이 사라진다. 현행 90%는 코드가 선언한 RIR 2~3에 정확히 착지한다. **1차 보고서의 90% 선택은 우연이 아니라 옳았다.**

> 💡 **감량폭과 반복 목표는 반드시 한 쌍으로 움직인다.**
> · 반복을 **유지**하려면 → 감량 **작게** (−5~15%)
> · 반복을 **늘리려면** → 감량 **크게** (−15~30%) + 목표 반복도 그만큼 올려야 함
> 사용자 정의(−30% + 15회 상한)가 어긋난 이유가 정확히 이것이다.

**[신규] 자가조절 규칙 — 탑세트가 무너지면 백오프를 한 스텝 더 내린다**

Khairallah 2009(EIU 석사논문 / *JSCR* 연구노트)는 11명에게 스쿼트·레그컬·레그익스텐션 3세트를 10RM으로 시키며 세트마다 0 / 5 / 10 / 15% 감량을 비교했다(휴식 1분). **스쿼트·레그컬은 15% 감량에서만 3세트 내내 10회를 유지**했고, 레그익스텐션은 감량 없이도 유지됐다.

즉 **필요한 감량폭은 휴식 길이·종목에 따라 다르다.** 앱은 180초를 쓰므로 10%로 충분한 경우가 대부분이지만, 탑세트에서 이미 반복이 무너졌다면(= 그날 컨디션이 나쁘거나 무게가 앞섬) 10%로는 부족하다.

```
탑세트 반복 < R.high  →  백오프 무게 = reduceWeight(W, 0.85, name)  (한 스텝 더)
탑세트 반복 ≥ R.high  →  백오프 무게 = reduceWeight(W, 0.90, name)  (현행)
```

Helms 2018(*JSCR*, 국가급 파워리프터 12명)도 같은 방향이다: 주간 부하 감량폭을 2 / 4 / 6%로 바꿨더니 상대 볼륨이 **74.6 / 88.4 / 114.4** 로 올라갔다(스쿼트·데드리프트에서 특히). **감량폭을 키우면 볼륨이 산다.** 근거등급 **중간**.

### 1-C. 탑세트 + 백다운 (top_backdown) — **신규 · 사용자 정의를 살린 안**

**정의**: 무거운 탑 1세트 → 무게를 크게 낮춰 **고반복으로 한계 근처까지**.

| 항목 | 처방 (**권장 수정판**) |
|---|---|
| 세트 수 | 워밍업 2~3 + 탑 1 + **백다운 2** (사용자 원안은 1세트 — 볼륨 손실 때문에 2로 올림) |
| 세트별 무게 | 탑 = **W** · 백다운 = **W × 0.825** (≈ −17.5%. 5kg 격자에서 −15~20%로 스냅) |
| 세트별 목표 횟수 | 탑 = R.high · 백다운 = **12~15회** |
| 세트 간 휴식 | 탑 후 180초 · 백다운 사이 **120초** (고반복은 회복이 상대적으로 빠름) |
| RIR 목표 | 탑 1~2 · 백다운 **0~1** (진짜 한계 근처) |
| 적합 종목 | **중강도 복합 · 머신 고중량 복합.** 프리웨이트 스쿼트·데드류에는 **비권장**(실패 근처 고반복 = 폼 붕괴) |
| 진행 규칙 | **탑세트 종속.** 탑이 오르면 백다운 무게도 자동으로 따라 오른다. 백다운 반복은 추세만 기록 |
| 근거등급 | **중간** — 구조 자체는 Goto 2004가 유일한 직접 근거. 82.5%라는 수치는 **낮음(계산 기반 추정)** |

**왜 70%가 아니라 82.5%인가**

탑세트가 10RM(≈75% 1RM)일 때:

| 백다운 배율 | 실제 1RM% | 한계 반복 | 탑 후 실제 가능 | **15회 목표 시 RIR** | 판정 |
|---|---|---|---|---|---|
| 0.70 (사용자 원안) | 52.5% | 24~27 | ~20 | **5~6** | ❌ 자극 미달 |
| 0.75 | 56% | 21~23 | ~17 | 2~3 | △ |
| **0.825** | **62%** | **~18** | **~15** | **0~1** | ✅ |
| 0.85 | 64% | ~17 | ~14 | −1(못 채움) | ✅ (12회로) |

Refalo 2023 메타분석: **실패에서 4~5회 이상 남기면 근비대가 뚜렷하게 떨어진다.** Robinson 2024 메타회귀: 실패에 가까울수록 커지되 **약 2 RIR 이후로는 기울기가 평탄**. → RIR 6은 명백히 손해 구간, RIR 0~1은 평탄 구간의 안쪽이다.

**직접 근거 — Goto 2004** (*JSCR* 18(4):730-737, 남성 16명, 10주)
고강도 5세트(90% 1RM) 뒤에 **저강도 고반복 1세트를 즉시 추가한 '콤비형'** 이, 고강도만 한 군보다 **1RM 레그프레스·최대 등속성 근력·근지구력에서 유의하게 우세**했고 **근단면적도 우세 경향**(p = 0.08)이었다. "무거운 세트 뒤에 가벼운 고반복 한 세트를 붙인다"는 아이디어의 **유일한 직접 실험 근거**다. 다만 근비대는 유의수준에 못 미쳤다(p = 0.08) — 과대해석 금지.

### 1-D. 어센딩 피라미드 (pyramid) — **신규 옵션**

**정의**: 세트마다 무게를 올리고 반복을 줄인다.

| 항목 | 처방 |
|---|---|
| 세트 수 | 워킹 3세트 (원 프로토콜은 3~5) |
| 세트별 무게 | **W × 0.85 → W × 0.925 → W** |
| 세트별 목표 횟수 | **R.high + 4 → R.high + 2 → R.high** (예: 12 → 10 → 8) |
| 세트 간 휴식 | 클래스 기본값 |
| RIR 목표 | 3~4 → 2~3 → 0~1 |
| 적합 종목 | 복합·고립 모두. **관절이 뻣뻣한 날의 대형 복합**에 특히 |
| 진행 규칙 | **마지막(가장 무거운) 세트가 R.high 도달** → 증량. 앞 세트는 자동으로 따라 오름 |
| 근거등급 | **중간** — 근비대는 스트레이트와 동등(Angleri 2017), 급성 지표도 차이 없음(IJSC 2024) |

**근거**
- **Angleri 2017**(잘 훈련된 남성 32명, 다리별 무작위 배정, 12주): CP 프로토콜 = 65% × 15회 → 70% × 12 → 75% × 10 → 80% × 8 → 85% × 6. 근단면적 **CP +7.5% vs TRAD +7.6%** — 차이 없음.
- **IJSC 2024 급성 연구**(잘 훈련된 남성 18명, 5세트, 종료 = 속도손실 25%, 휴식 5분): 어센딩(65-70-75-80-85%)은 **일정부하(75% 고정)와 아무 차이가 없었다.** 볼륨·반복·속도·RPE 전부.
- **ACSM *Health & Fitness Journal* 2021 리뷰**: 선형(DeLorme)·역(Oxford) 둘 다 유효, 근력·근비대 동등. 다만 **어센딩은 훈련 중 불쾌감이 더 컸다.**

**약점**: 첫 세트가 RIR 3~4로 시작하므로, 3세트 중 1세트가 준(準)워밍업이 된다. 볼륨 대비 자극 효율이 스트레이트보다 낮다.
**앱 판정**: **옵션으로만.** 기본 배정 안 함.

### 1-E. 역피라미드 / RPT (rpt) — **신규 옵션**

**정의**: 첫 세트가 가장 무겁고, 세트마다 감량하며 반복을 늘린다.

| 항목 | 처방 |
|---|---|
| 세트 수 | 워킹 3세트 |
| 세트별 무게 | **W → W × 0.90 → W × 0.80** |
| 세트별 목표 횟수 | **R.high → R.high + 2 → R.high + 4** |
| 세트 간 휴식 | 클래스 기본값 (첫 세트 후엔 +30초 권장) |
| RIR 목표 | 전 세트 0~2 |
| 적합 종목 | 중강도 복합·고립. **프리웨이트 대형 복합에는 비권장**(첫 세트부터 실패 근처) |
| 진행 규칙 | **첫(가장 무거운) 세트가 R.high 도달** → 증량. 뒤 세트는 종속 |
| 근거등급 | **낮음** — 직접 근비대 연구가 거의 없다 |

**근거**
- **IJSC 2024**: 디센딩(85-80-75-70-65%)은 어센딩·일정부하와 볼륨은 같았지만 **최대속도와 세트 RPE가 유의하게 낮았다**(p ≤ 0.05). 저자 결론: *"AP·CL·DP 모두 쓸 만하나 DP는 최대속도에 불리할 수 있다."*
- **ACSM 2021 리뷰**: 디센딩은 **훈련 중 쾌감(pleasure)이 더 컸다** — 지속률 측면의 이점.
- 근비대 우위를 보인 유일한 연구는 미훈련 여성 대상 소규모 연구 하나이고, **근손상 지표도 함께 높았다**.

**구조적 사실**: RPT는 수학적으로 **탑세트+백오프의 다세트 확장판**이다. 별도 스킴으로 유지하는 실익은 "반복이 세트마다 늘어난다"는 점 하나뿐이다.
**앱 판정**: **옵션으로만.** 사용자가 요청했으므로 넣되, 기본 배정하지 않는다.

### 1-F. 드롭세트 (drop) — 현행 조건부 제안

| 항목 | 처방 (현행 유지) |
|---|---|
| 세트 수 | 워킹 3세트 + **마지막 세트에만** 드롭 2회 연장 |
| 세트별 무게 | 본세트 W → 드롭1 **W × 0.75** → 드롭2 **드롭1 × 0.75** |
| 세트별 목표 횟수 | 본세트 R.low~R.high · 드롭 **실패까지** |
| 드롭 사이 휴식 | **0~10초** (무게 바꾸는 시간만) |
| RIR 목표 | 본세트 0~1 · 드롭 **0** |
| 적합 종목 | **머신·케이블 고립**(안정성이 높아 실패 지점에서도 안전). `compound_heavy` 금지 |
| 진행 규칙 | 드롭 세트는 진행 판정·볼륨 카운트에서 **제외**(마지막 워킹세트의 연장) |
| 근거등급 | **높음** — 근비대 동등, 시간 절감은 실측됨 |

**갱신된 근거 (2026)**
**Havers 등 2026**(*Sports Medicine – Open*, 12연구·274명):
- 근비대 **SMD 0.04** [−0.29, 0.36] · 근력 **SMD −0.04** [−0.34, 0.26] → **완전 동등**
- 급성 비용: **RPE SMD 1.62** (p = 0.014) · **젖산 SMD 0.67** (p = 0.006) · 반동점프·최대힘·최대파워 감소가 더 큼
- 시간: 전통의 **1/2 ~ 1/3**
- 저자 권고: *"전면 대체가 아니라 특정 시기·특정 근육군에만 전략적으로."* **고빈도 프로그램에서는 피로 누적을 관리해야 한다.**

→ **주 5일 PPLUL 사용자에게 "고빈도 주의"는 정확히 해당된다.** 현행의 빡센 제안 조건(주 1회 상한·시간 압박 시에만·마지막 세트만)은 그대로 유지가 맞다.

### 1-G. 마이오렙 (myo_reps) / 레스트-포즈 (rest_pause) — **분리 권장**

1차 보고서는 둘을 한 항목으로 묶었지만, **처방이 다르므로 분리하는 게 정확하다.**

#### G-1. 마이오렙 (myo_reps) — 고반복 활성화형

| 항목 | 처방 (현행 + 정밀화) |
|---|---|
| 세트 수 | 활성화 1세트 + 미니세트 **3~5** |
| 무게 | **전부 W로 동일** (변경 없음) |
| 목표 횟수 | 활성화 = R.low~R.high 실패 근접 · 미니 = **3~5회** |
| 사이 휴식 | **15~20초** (깊은 호흡 3~5회) |
| RIR 목표 | 전부 0~1 |
| 종료 조건 | 미니세트가 **3회 미만으로 떨어지면 중단** |
| 적합 종목 | **프리웨이트 고립**(무게를 안 바꾸므로 덤벨·바벨에서 안전). 대형 복합은 심폐가 먼저 지쳐 부적합 |
| 근거등급 | **중간** — RCT 1편 |

**근거**: **Bradshaw 등 2026**(*JSCR* 40(6):638-649, 8주, n = 22, 벤치 계열 3종목 주 2회): 근비대·근력 **동등**(둘 다 p < 0.001 증가, 군간 차이 없음), 마이오렙이 **볼륨 로드 약 30% 적음**, **세션 시간 유의하게 짧음**(p < 0.001).

#### G-2. 레스트-포즈 (rest_pause) — 고중량 총반복형 · **신규**

| 항목 | 처방 |
|---|---|
| 세트 수 | **총 반복 목표에 도달할 때까지** (세트 수가 아니라 반복 총량이 목표) |
| 무게 | **80% 1RM 상당 = 대략 W** (고정) |
| 목표 횟수 | **총 18회** 를 채울 때까지 쪼개서 수행 (예: 8 + 5 + 3 + 2) |
| 사이 휴식 | **20초** |
| RIR 목표 | 매 미니세트 0 |
| 적합 종목 | 중강도 복합 · 머신 고중량 복합 |
| 근거등급 | **중간** — RCT 1편 + 2026 메타에서 "레스트포즈만 근비대에 소폭 우위 경향" |

**근거**: **Prestes 등 2019/2021**: RP군 = 80% 1RM, 세트 간 20초, **총 18회 채울 때까지** vs 전통군 = 3 × 6회 @ 80%, 휴식 2~3분. 근력·근비대 **동등**, 세션 시간 **35분 vs 57분**. Tsartsapakis 2026 메타는 여러 고급 기법 중 **레스트포즈만 근비대에서 소폭 유리한 경향**을 보였다고 언급했다(다만 전체 g는 유의하지 않음).

**마이오렙과의 차이**: 마이오렙은 "가벼운 무게 + 고반복 활성화 후 짧은 미니세트", 레스트포즈는 "무거운 무게 + 총 반복 목표". 앱에서는 **고립 = 마이오렙 / 복합 = 레스트포즈** 로 나누는 게 자연스럽다.

### 1-H. 클러스터 세트 (cluster) — **신규 · 허리 사용자에게 실질 가치 있음**

**정의**: 한 세트를 여러 덩어리로 쪼개고 **세트 안에서** 짧게 쉰다. 세트 수·반복 수는 그대로.

| 항목 | 처방 |
|---|---|
| 세트 수 | 워킹 3세트 (각 세트를 **3덩어리 × 4회**로 분할) |
| 무게 | **전부 W** (감량 없음) |
| 세트별 목표 횟수 | 12회 = 4 + 4 + 4 |
| **덩어리 사이(인트라) 휴식** | **20초** |
| 세트 간 휴식 | 클래스 기본값 (180초) |
| RIR 목표 | 마지막 덩어리 0~1 |
| 적합 종목 | 고중량 복합 · 머신 복합. **폼이 무너지기 시작하는 종목** |
| 진행 규칙 | 3덩어리를 다 채우면 → 증량 (스트레이트와 동일한 더블 프로그레션) |
| 근거등급 | **중간** — 근비대 동등이 볼륨·노력 매칭 RCT로 확인됨 |

**근거**
- **2025 EJAP**(훈련자 10명, 8주, 편측 레그프레스·레그익스텐션, **볼륨과 노력 둘 다 매칭**): CS = 3덩어리 × 4회 + 인트라 20초 / TS = 5 × 12, 둘 다 RIR 0~1, 세트 간 3분.
  제지방 **CS +171.8 g vs TS +201.1 g (p = 0.272)** · 대퇴직근 두께 **CS +0.24 cm vs TS +0.17 cm (p = 0.297)** → **동등**.
- **Jukic 등 2020**(*Sports Medicine* 메타): 클러스터는 **세트 내 속도 유지에 유리**. 휴식 재분배(rest-redistribution)보다 클러스터가 속도 유지에 더 낫다.
- **Frontiers 2025 메타**: 장기 클러스터 훈련의 최대근력 효과 — 전통과 비교.

**앱에서 왜 가치가 있나**: 근비대 이득은 0이지만 **"무거운 무게로 마지막 반복까지 폼을 지킨다"** 는 이득이 있다. 사용자는 허리디스크 보유자이고, 실패 근처 고반복에서의 폼 붕괴가 가장 피하고 싶은 것이다. **드롭·마이오렙이 "시간을 사는" 옵션이라면, 클러스터는 "폼을 사는" 옵션이다.** 이건 앱에 없던 축이다.

## 2) 탑세트 구조 비교 판정

### 2-A. 세 후보의 정확한 정의

| | (a) 현행 | (b) 사용자 정의 | (c) 문헌·실무 표준들 |
|---|---|---|---|
| 워밍업 | W×0.50 × 8회 → W×0.75 × 4회 | 탑의 **50% × 12~15회** | 1~2세트, **최소 하나는 80~90% 1RM** |
| 피더 | 없음 | 탑의 **80~90% × 4~6회** | (= 위 워밍업의 마지막 단) |
| 탑세트 | **W × R.high(5~8회)**, RIR 1~2 | **100% × 8~12회** | c1: 3~5회 @RPE 8-9 / c2: 8~12회 @80-85% 1RM |
| 백오프·백다운 | **W×0.90 × 같은 횟수 × 2세트**, RIR 2~3 | **70% × 한계 근처, 최대 15회** | c1: 탑의 85~90% × 8~12회 × 2~3세트<br>c2: 탑의 70~80% × 8~12회 × 2~3세트<br>c4(Helms): 탑에서 **−2~6%** 씩, RPE 재도달까지 |
| 워킹세트 수 | **3** | **2** (탑1+백다운1) | 3~4 |

### 2-B. 판정 ① — 탑세트 반복(5~8 vs 8~12)은 **서로 다른 클래스 얘기다**

사용자 정의의 "탑세트 8~12회"는 앱의 `compound_heavy`(5~8회)가 아니라 **`compound_moderate`(8~12회)에 정확히 대응한다.**

- 사용자가 아는 탑세트 = **보디빌딩식**(탑세트도 8~12회, 목적은 근비대 자극)
- 앱의 `compound_heavy` = **파워빌딩식**(탑세트 5~8회, 목적은 고부하 노출 + 1RM 추적 신선도)

**둘 다 맞다. 다른 클래스에 배정하면 충돌이 사라진다.** 앱은 이미 클래스 체계를 갖고 있으므로 새 개념이 필요 없다.

> 앱이 `compound_heavy`를 5~8회로 두는 실제 이유가 하나 더 있다: **e1RM 추정 정확도**. `ROLLING_1RM_MAX_REPS = 12`라 12회 초과 세트는 1RM 갱신에서 빠진다. 탑세트를 8~12회로 올리면 e1RM 신호가 흐려진다.

### 2-C. 판정 ② — 백다운 70%는 "최대 15회"와 짝이 안 맞는다

§1-C의 표를 다시 놓는다. 탑세트가 10RM(≈75% 1RM)일 때:

| 백다운 배율 | 실제 1RM% | 탑세트 후 실제 가능 반복 | **15회 목표 시 RIR** |
|---|---|---|---|
| **0.70 (사용자 원안)** | 52.5% | ~20회 | **5~6** ← Refalo 2023 기준 **자극 미달 구간** |
| **0.825 (권장)** | 62% | ~15회 | **0~1** ✅ |

**"한계 근처까지"와 "최대 15회"는 70%에서 동시에 성립할 수 없다.** 둘 중 하나를 골라야 한다:
- 정말 한계까지 → **20회 이상**. 대형 복합에서는 심폐가 먼저 지치고, 폼이 무너진다(허리디스크 보유자에게 최악)
- 15회에서 끊기 → **무게를 82.5%로 올려야** 15회가 한계 근처가 된다

→ **권장: 82.5% × 12~15회 × RIR 0~1.**

### 2-D. 판정 ③ — 볼륨·시간·피로 실측 비교 (벤치 프레스 예시, W = 65 kg)

| | (a) 현행 탑+백오프 | (b) 사용자 원안 | **(b′) 권장 수정판** |
|---|---|---|---|
| 세트 구성 | 65×8 / 60×8 / 60×8 | 65×10 / 45×15 | 65×8 / 55×14 / 55×14 |
| 워킹세트 수 | **3** | **2** | **3** |
| 총 반복 | 24 | 25 | 36 |
| 볼륨 로드 | **1,480 kg** | **1,325 kg** | **2,060 kg** |
| 종목당 소요 | **~10분** | ~9분 | **~13분** |
| 마지막 세트 RIR | 2~3 | 6 (자극 미달) | 0~1 |
| 주간 세트 카운트 기여 | 3 | **2 (−33%)** | 3 |

> 표 읽는 법: 세 안을 **같은 W(65 kg)** 로 놓고 비교했다. 엄밀히는 (b)의 탑세트는 정의상 8~12회짜리라 W가 더 가벼워야 하지만(§2-B), 여기서 보려는 건 **구조가 만드는 세트 수·볼륨·시간의 차이**라 기준을 통일했다. 무게가 달라져도 결론(워킹세트 2 vs 3)은 바뀌지 않는다.

**핵심**: 사용자 원안의 가장 큰 실제 손실은 %도 AMRAP도 아니라 **워킹세트가 3 → 2로 줄어 주간 볼륨이 33% 깎이는 것**이다. 볼륨은 근비대에서 **유일하게 확립된 용량 변수**다(Schoenfeld 용량-반응 메타). 그래서 권장 수정판은 백다운을 2세트로 되돌린다.

### 2-E. 판정 ④ — 이 앱에 대한 최종 권장

> **현행 탑+백오프 골격을 유지하고, 세 군데만 고친다.**

**① 워밍업 램프에 피더 1단 추가** (`compound_heavy`)
```
현행:  W×0.50 × 8회  →  W×0.75 × 4회
권장:  W×0.50 × 8회  →  W×0.75 × 4회  →  W×0.90 × 2회    ← 신규 (휴식 45초)
```

**② 마지막 백오프만 RIR 0~1**
탑 1~2 / 백오프① 2~3 / **백오프② 0~1**. 사용자가 원하는 "한계까지 한 세트"를 볼륨 손실 없이 흡수한다. 근거: Robinson 2024(실패 근접도가 근비대에 특이적, 약 2 RIR 이후 평탄) + Havers 2026(전 세트를 실패로 밀면 피로만 크고 이득 0).

**③ 탑세트가 무너지면 백오프를 한 스텝 더**
```
탑세트 반복 < R.high  →  백오프 = reduceWeight(W, 0.85, name)
탑세트 반복 ≥ R.high  →  백오프 = reduceWeight(W, 0.90, name)   (현행)
```
근거: Khairallah 2009 · Helms 2018.

**④ 사용자 정의 구조는 `top_backdown` 스킴으로 시트에 넣는다** — 기본 배정은 하지 않는다.

### 2-F. 판정 ⑤ — 피더세트 = 램프업 워밍업의 마지막 단. **합쳐야 한다**

**피더세트의 정의**(John Meadows 계열 원문): *"신경계를 깨우고 그 동작에 익숙해지게 하는, 총 부하는 훨씬 적은 세트."* 워밍업과의 차이는 **"워킹세트에 종속되느냐"** — 피더는 에너지를 아껴 주고, 나쁜 워밍업은 에너지를 빼앗아 간다.

한 실무 프로토콜의 예(워킹 10~12회 기준): 30% × 10 → 50% × 6~8 → **75% × 4~6 → 85~90% × 1~2**.

**이건 "잘 만든 램프업 워밍업"의 정의와 같다.** 별개의 세트 종류가 아니다.

**과학이 지지하는 것**
- 이득을 보인 웜업 프로토콜은 **1~2세트이고, 최소 하나가 80~90% 1RM** 이며 부하가 점진 증가했다.
- 8회 @ ~64% 1RM 워밍업이 8회 @ ~32% 보다 이후 3 × 6 @ 80% 수행을 개선했다.
- 두 번째 워밍업을 **90% 1RM**으로 하면 45% 1RM보다 개선폭이 컸다.
- **De Freitas PAP 실험**: 2회 @ 90% 1RM 뒤 4 × AMRAP @ 70% → **첫 AMRAP 22회 vs 15회**(비교군). 단 **세트 2~4는 차이 없음** — 이득은 첫 세트에만 국한된다.

**판정**
| 질문 | 답 |
|---|---|
| 피더세트는 램프업과 다른가? | **아니다.** 램프의 상단부를 부르는 다른 이름이다 |
| 앱에 별도 세트 역할로 넣어야 하나? | **아니다.** `role: 'warmup'` 안에서 무게·반복만 바꾸면 된다 |
| 그럼 뭘 고쳐야 하나? | 현행 램프가 **W×0.75에서 멈춘다.** 근거는 마지막 단을 더 무겁게·더 적은 반복으로 가라고 말한다 → **W×0.90 × 2회 추가** |
| 근거등급 | 급성 수행 개선 = **중간** · **근비대 개선 근거는 없음(등급 없음)** |
| 사용자 원안(50% × 12~15회 웜업)은? | **반복이 너무 많다.** 12~15회 웜업은 준비가 아니라 피로다. **8회로 줄이는 게 맞다** |

> ⚠️ **"85~90%"라는 숫자를 두 번 세면 안 된다.** 연구가 말한 85~90%는 **1RM 기준**이고, 실험의 워킹세트는 80% 1RM이었다 — 즉 그 웜업 단은 **워킹 무게보다 무거운 1~2회 단발**이었다(전형적인 PAP). 반면 이 문서가 권하는 `W × 0.90`은 **워킹 무게 기준 90%**(= 8RM 기준 약 72% 1RM)로, 훨씬 보수적인 번역이다.
> **일부러 보수적으로 잡았다.** 워킹 무게를 넘는 단발 웜업은 허리디스크 보유 초중급자에게 위험 대비 이득이 맞지 않고, De Freitas 실험에서도 그 이득은 **첫 세트 한 번뿐이었다**. 사용자 원안의 "탑의 80~90%"도 같은 이유로 그대로 쓸 만하다 — 다만 반복은 4~6회가 아니라 **2~3회**여야 피로가 안 남는다.

## 3) 자동 배정 vs 옵션 — 재설계안

### 3-A. 원칙

> **기본 배정은 바꾸지 않는다.**
> 세트법 간 근비대 차이는 메타 3편이 전부 "0"이라고 말한다(Tsartsapakis 2026 g = 0.046 p = 0.370 · Havers 2026 SMD 0.04 · Angleri 2017). **기본값을 흔들 근거가 없다.** 대신 **선택지를 넓히고, 각 선택지가 무슨 문제를 푸는지 명확히 적는다.**

### 3-B. 클래스 × 세트법 배정표

범례: **●기본(자동)** · ○옵션 · △조건부(경고 표시) · ✕차단

| 세트법 | compound_heavy | compound_moderate | isolation | light_isolation | rehab |
|---|---|---|---|---|---|
| `straight` | ○ | **●** | **●** | **●** | **●고정** |
| `top_backoff` | **●** | ○ | △ | ✕ | ✕ |
| `top_backdown` 🆕 | ○ | ○ **추천 표시** | ○ | △ | ✕ |
| `pyramid` 🆕 | ○ | ○ | ○ | △ | ✕ |
| `rpt` 🆕 | ○ | ○ | ○ | △ | ✕ |
| `cluster` 🆕 | ○ **추천 표시**\* | ○ | △ | ✕ | ✕ |
| `drop` | △ 경고 | △ 머신만 | ○ **추천**(머신·케이블) | ○ **추천** | ✕ |
| `myo_reps` | △ 경고 | △ | ○ **추천**(프리웨이트) | ○ **추천** | ✕ |
| `rest_pause` 🆕 | ○ | ○ **추천**(시간 압박 시) | △ | ✕ | ✕ |

\* 클러스터 "추천 표시" 조건: 해당 종목에 **최근 14일 통증 기록이 있거나**(`hasRecentPain`) 사용자가 폼 우려를 표시했을 때. "무게를 낮추지 않고 폼을 지키는" 유일한 옵션이기 때문.

**차단(✕) 규칙**
- `rehab`은 전부 차단 — 현행 `lockScheme` 그대로.
- `light_isolation`에 `top_backoff`/`cluster`/`rest_pause` 차단 — 15~25회 범위에서 탑세트·클러스터는 의미가 없다.
- 무게를 모르는 종목(맨몸·미측정)은 감량 기반 스킴(`top_backoff`/`top_backdown`/`drop`/`pyramid`/`rpt`)이 성립하지 않는다 → 현행 `effectiveSetScheme`가 스트레이트로 접는 로직을 **새 스킴에도 확장**해야 한다.

### 3-C. AMRAP(한계반복) 세트의 기록·진행 추적 설계

새로 들어오는 스킴 중 **`top_backdown`의 백다운 세트**와 **`rpt`의 마지막 세트**가 사실상 AMRAP 성격이다. 현행 더블 프로그레션과 어떻게 맞물리는지 정리한다.

#### C-1. 현행 진행 판정이 이미 안전한 부분 ✅

```js
function reachedTopAt(perf, weight) {
  var ws = perf.sets.filter(function(s) {
    if (s.role === 'drop' || s.role === 'myo') return false;
    return s.weight === weight && s.reps > 0 && !s.isWarmup;   // ← 최대 무게 세트만
  });
  return ws.length > 0 && ws.every(function(s) { return s.reps >= topReps; });
}
```
`s.weight === maxW` 필터 때문에 **백다운(82.5%)은 자동으로 판정에서 빠진다.** 코드를 고칠 필요가 없다. `role` 예외 목록에 `'backdown'`을 추가할 필요조차 없다(무게가 이미 다르므로).

> ⚠️ 단 하나의 예외: **역방향(어시스트) 종목**. 보조 무게가 격자에 걸려 백다운과 탑이 같은 값으로 스냅될 수 있다. `role` 필터에 `'backdown'`을 넣어 두는 편이 안전하다.

#### C-2. e1RM 오염도 이미 막혀 있다 ✅

`ROLLING_1RM_MAX_REPS = 12` — **12회 초과 세트는 1RM 갱신에서 제외**된다. 백다운은 12~15회를 노리므로 대부분 자동 배제된다. 12회 이하로 끝나도 무게가 82.5%라 e1RM이 탑세트보다 낮게 나오고, `update1RM`은 rolling max를 쓰므로 값을 끌어내리지 않는다.

#### C-3. 진행 원천은 **탑세트 하나로 유지한다** (핵심 설계 결정)

| 후보 | 내용 | 판정 |
|---|---|---|
| A. 백다운도 독립 더블 프로그레션 | 백다운이 15회 2세션 연속 → 백다운만 +1 step | ❌ **기각.** 진행 원천이 둘이면 사용자가 이해 못 하고, AMRAP 변동성(하루 컨디션에 ±3회)이 신호를 덮는다 |
| **B. 탑세트 종속** | 백다운 무게 = `reduceWeight(W, 0.825)`. 탑이 오르면 자동으로 따라 오름 | ✅ **채택.** 단순하고, 현행 코드와 충돌 0 |

**AMRAP 반복은 "추세 표시"로만 쓴다.** 진행 판정에는 넣지 않되 화면에는 보여 준다:
```
백다운 55kg — 지난번 13회
```
이건 이미 있는 `getRecentPerformances(name, 3)` 캐시로 만들 수 있다. 새 저장소가 필요 없다.

#### C-4. 볼륨 카운트에는 **포함**한다

```js
function countWorkingSets(sets) {
  return sets.filter(function(s) {
    return s && s.completed && !s.isWarmup && s.role !== 'drop' && s.role !== 'myo';
  }).length;
}
```
`drop`·`myo`는 "마지막 워킹세트의 연장"이라 제외됐지만, **백다운은 독립된 워킹세트다.** 무게·휴식·목표가 따로 있고 볼륨 로드에 크게 기여한다. **예외 목록에 넣지 않는다** — 위 코드가 그대로 옳다.

같은 이유로 `cluster`의 덩어리는 **한 세트로 세야 한다**(4+4+4 = 1세트). 이건 세트 배열을 어떻게 만드느냐의 문제다 → §4-B 참조.

#### C-5. 세트 입력 UI

| 세트 역할 | 목표 표시 | 입력 허용 |
|---|---|---|
| 일반 워킹 | `8회` | 자유 |
| **백다운(AMRAP)** | `12~15회 · 한계까지` | **상한 없이 자유** (18회를 쳐도 저장돼야 함) |
| 드롭·미니 | `실패까지` | 자유 |

현행 세트 입력이 이미 자유 입력이므로 **표시 문구만 바꾸면 된다.**

## 4) 앱 반영 설계 초안

### 4-A. `SET_SCHEMES` 확장 스키마 — 세트 생성 규칙을 데이터로

현행은 `kr` / `short` / `desc` 3개 필드뿐이고, 실제 세트 생성은 `buildSchemeSets()` 안의 **if/else 분기**에 하드코딩돼 있다. 스킴이 4개 → 9개가 되면 이 분기가 관리 불가능해진다.

**권장: 생성 규칙을 데이터로 내리고, `buildSchemeSets`는 패턴 4종만 해석하게 한다.**

```js
// 패턴 4종 (이것만 코드가 안다)
//  uniform  : 전 세트 동일 무게·반복
//  ramp     : steps 배열대로 세트마다 무게 배율·반복 가감
//  extend   : 마지막 워킹세트 뒤에 연장 세트를 붙임 (독립 세트로 세지 않음)
//  cluster  : 한 세트를 chunk 회씩 쪼개고 사이에 intraRest 를 넣음
var SET_SCHEMES = {
  straight: {
    kr: '스트레이트', short: '스트레이트',
    desc: '모든 세트를 같은 무게·횟수로',
    build: { pattern: 'uniform', rir: { compound: '2-3', other: '0-2' } }
  },

  top_backoff: {
    kr: '탑세트 + 백오프', short: '탑+백오프',
    desc: '가장 무거운 1세트 → 90% 무게로 같은 횟수',
    build: {
      pattern: 'ramp',
      steps: [
        { pct: 1.00, repsDelta: 0, rir: '1-2', role: 'top' },
        { pct: 0.90, repsDelta: 0, rir: '2-3', role: 'backoff', repeat: 'fill' },
        { pct: 0.90, repsDelta: 0, rir: '0-1', role: 'backoff', last: true }  // 마지막만 한계 근처
      ],
      // 탑세트가 목표 반복 미달이면 백오프를 한 스텝 더 내린다 (Khairallah 2009)
      autoDeload: { when: 'topMissedTarget', pct: 0.85 }
    }
  },

  top_backdown: {                                   // 🆕
    kr: '탑세트 + 백다운', short: '탑+백다운',
    desc: '무거운 1세트 → 82% 무게로 12~15회 한계까지',
    build: {
      pattern: 'ramp',
      steps: [
        { pct: 1.000, repsDelta: 0,  rir: '1-2', role: 'top' },
        { pct: 0.825, repsAbs: [12, 15], rir: '0-1', role: 'backdown',
          amrap: true, rest: 120, repeat: 'fill' }
      ]
    }
  },

  pyramid: {                                        // 🆕 어센딩
    kr: '피라미드', short: '피라미드',
    desc: '가볍게 시작해 세트마다 무게를 올려요',
    build: {
      pattern: 'ramp',
      steps: [
        { pct: 0.850, repsDelta: +4, rir: '3-4', role: 'work' },
        { pct: 0.925, repsDelta: +2, rir: '2-3', role: 'work' },
        { pct: 1.000, repsDelta:  0, rir: '0-1', role: 'top'  }
      ],
      progressFrom: 'last'      // 증량 판정 기준 = 가장 무거운 마지막 세트
    }
  },

  rpt: {                                            // 🆕 역피라미드
    kr: '역피라미드', short: '역피라미드',
    desc: '가장 무거운 1세트부터, 세트마다 가볍고 길게',
    build: {
      pattern: 'ramp',
      steps: [
        { pct: 1.00, repsDelta:  0, rir: '0-2', role: 'top'  },
        { pct: 0.90, repsDelta: +2, rir: '0-2', role: 'work' },
        { pct: 0.80, repsDelta: +4, rir: '0-2', role: 'work' }
      ],
      progressFrom: 'first'
    }
  },

  cluster: {                                        // 🆕
    kr: '클러스터', short: '클러스터',
    desc: '한 세트를 4회씩 쪼개고 20초씩 쉬어요',
    build: { pattern: 'cluster', chunk: 4, intraRest: REST_CLUSTER_SEC, rir: '0-1' }
  },

  drop: {
    kr: '드롭세트', short: '드롭',
    desc: '마지막 세트에서 무게를 25%씩 낮춰 이어서',
    build: {
      pattern: 'extend',
      steps: [
        { pct: DROP_PCT,          repsMode: 'toFailure', rest: REST_DROP_SEC, role: 'drop' },
        { pct: DROP_PCT * DROP_PCT, repsMode: 'toFailure', rest: null,        role: 'drop' }
      ],
      countsAsSet: false          // 볼륨 카운트에서 제외
    }
  },

  myo_reps: {
    kr: '마이오렙', short: '마이오렙',
    desc: '마지막 세트 후 20초 쉬고 미니세트 반복',
    build: {
      pattern: 'extend',
      steps: [{ pct: 1.0, repsAbs: [3, 5], rest: REST_MYO_SEC, role: 'myo', repeat: 3 }],
      countsAsSet: false,
      stopWhen: 'minisetBelow3'
    }
  },

  rest_pause: {                                     // 🆕
    kr: '레스트포즈', short: '레스트포즈',
    desc: '같은 무게로 20초씩 쉬며 총 18회를 채워요',
    build: { pattern: 'extend', totalReps: 18, rest: REST_MYO_SEC, role: 'myo', countsAsSet: false }
  }
};

// 신규 상수
var BACKDOWN_PCT     = 0.825;  // 탑의 82.5% — 12~15회가 RIR 0~1에 착지하는 지점 (§1-C 계산)
var BACKOFF_DELOAD_PCT = 0.85; // 탑세트가 목표 미달일 때의 백오프 (Khairallah 2009)
var FEEDER_PCT       = 0.90;   // 워밍업 램프 마지막 단 (§2-F)
var REST_CLUSTER_SEC = 20;     // 클러스터 덩어리 사이
var REST_BACKDOWN_SEC = 120;   // 백다운 사이 (고반복은 회복이 빠름)
```

**이 구조가 주는 것**
1. 새 스킴 추가 = **데이터 한 덩어리 추가**. `buildSchemeSets`를 안 건드린다.
2. 미리보기(`describeSetStructure`)가 `steps`를 읽어 자동으로 문장을 만든다 — **화면과 세션이 어긋날 수 없다**(현행이 이미 쓰는 원칙).
3. 테스트가 데이터 표 자체의 무결성을 검사할 수 있다(`pct`가 0~1, `rir` 형식, `repsDelta`가 클래스 범위를 안 넘는지).

### 4-B. `buildSchemeSets` 변경점

```
현행: if (scheme === 'top_backoff') { ... } else { ... }   ← 스킴마다 분기
권장: var b = SET_SCHEMES[scheme].build;
      switch (b.pattern) {
        case 'uniform': …
        case 'ramp':    b.steps 를 순회하며 세트 생성 (repeat:'fill' 은 남은 세트 수만큼 반복)
        case 'cluster': 워킹세트마다 chunk 회 × N 덩어리, 사이 intraRest
        case 'extend':  마지막 워킹세트 뒤에 연장 (countsAsSet:false)
      }
```

**반드시 지켜야 할 기존 계약 4가지**
| 계약 | 이유 |
|---|---|
| `sets: 0` 은 유효한 값 (남은 워킹세트 없음) | 현행 주석이 명시 — "마지막 세트를 드롭으로" 요청의 정확한 의미 |
| 무게 없는 종목은 감량 스킴을 스트레이트로 접는다 | `effectiveSetScheme` — **새 스킴 5종에도 확장 필요** |
| 역방향(어시스트)은 감량 = 보조 **증가** | `reduceWeight`가 이미 처리. 새 스킴의 `pct`도 이 함수를 통과시켜야 함 |
| `reduceWeight`는 최소 1 step 하강 보장 | 반올림으로 감량이 사라지는 함정 방어 |

**클러스터의 세트 배열 표현 — 두 가지 안**

| 안 | 표현 | 장점 | 단점 |
|---|---|---|---|
| A. 덩어리를 세트 배열의 원소로 | `{role:'cluster', reps:4, rest:20} × 3` | 화면·타이머가 기존 로직 그대로 | **볼륨 카운트가 3배**로 잡힘 → `countWorkingSets` 예외 필요 |
| **B. 한 세트 안에 덩어리 정보** | `{role:'work', reps:12, chunks:[4,4,4], intraRest:20}` | 볼륨 카운트가 저절로 맞음 | 세션 화면·휴식 타이머에 새 로직 필요 |

→ **A안 + `countWorkingSets` 예외 추가**를 권한다. 세션 화면·타이머·완료 처리가 전부 "세트 배열의 원소" 단위로 짜여 있어서, B안은 건드릴 곳이 훨씬 많다. `role: 'cluster'`를 `drop`·`myo`와 같은 예외 목록에 넣되, **덩어리 3개 중 첫 번째만 세는** 규칙이 필요하다(또는 `chunkIndex: 0` 플래그).

### 4-D. 미리보기 표기

현행 `describeSetStructure()`는 **실제로 만들어진 세트 배열에서 세어** 문장을 만든다(하드코딩 금지). 이 원칙을 새 스킴에도 그대로 적용하면 다음이 자동으로 나온다:

| 스킴 | 미리보기 한 줄 |
|---|---|
| `top_backoff` | `탑세트 1 + 백오프 2 (90% · RIR 2-3)` |
| `top_backdown` | `탑세트 1 + 백다운 2 (82% · 12~15회 · RIR 0-1)` |
| `pyramid` | `3세트 (85% → 92% → 100%)` |
| `rpt` | `탑세트 1 + 2세트 (90% · 80%)` |
| `cluster` | `3세트 × 4+4+4 (사이 20초)` |
| `rest_pause` | `총 18회 (20초씩 쉬며)` |

**처방 표(2단계 미리보기)의 '세트' 열**: 백다운·클러스터는 **워킹세트로 센다**(3). 드롭·미니는 세지 않는다(현행 규칙 유지).
**'RIR' 열**: 첫 워킹세트 기준이라 탑세트 값(1-2)이 뜬다 — 세트마다 다르면 아래 구성 줄이 풀어 준다(현행 로직 그대로 동작).

### 4-E. 리스크 · 체크리스트

| 항목 | 내용 |
|---|---|
| ⚠️ **`effectiveSetScheme` 확장 누락** | 무게를 모르는 종목에서 새 스킴 5종이 안 접히면 **미리보기와 실제 세트가 어긋난다**. `top_backdown`·`pyramid`·`rpt`를 접기 목록에 추가 필수 |
| ⚠️ **역방향(어시스트) 종목 설명 반전** | `pct`가 낮을수록 "쉬워진다"는 전제가 어시스트에선 뒤집힌다. 현행이 `top_backoff`·`drop`에 대해 하는 `desc` 치환을 **새 5종에도** 해야 함 |
| ⚠️ **`countWorkingSets`의 클러스터 처리** | 덩어리 3개를 3세트로 세면 주간 볼륨이 3배로 부풀어 **AI 프롬프트·부족 부위 판정이 통째로 오염**된다 |
| ⚠️ **`clampRepsToClass` 와 `repsDelta` 충돌** | 피라미드·RPT의 `repsDelta: +4`가 클래스 상한을 넘는다(`compound_heavy` 5-8 → 12회). **스킴이 만든 세트 반복은 클램프 대상에서 빼거나**, 클래스 상한을 스킴별로 완화해야 함 — **가장 놓치기 쉬운 지점** |
| ⚠️ **역방향 + 백다운 무게 충돌** | 보조 무게가 격자에 걸려 탑과 백다운이 같은 값으로 스냅되면 `reachedTopAt`이 백다운을 탑으로 오인한다 → `role` 필터에 `'backdown'` 추가 |
| 📋 **테스트** | 새 전역 상수·함수는 `tests/golden-symbols.json` 갱신. `SET_SCHEMES` 표 자체의 무결성 테스트(`pct` 범위·`rir` 형식) 신설 권장. `node --test tests/characterization.test.mjs` |
| 📋 **배포** | `service-worker.js` `CACHE_VERSION` 상향 + `APP_VERSION` 동기화 |
| 📋 **하위호환** | 진행 중 세션(`fitness_active_session`)에 `role: 'backdown'`/`'cluster'`가 없어도 깨지지 않아야 함. `SET_ROLE_KR`에 없는 role은 뱃지를 안 그리는 현행 동작이 이미 방어 |
| 📋 **저장된 override 정리** | `KEYS.SET_SCHEMES`에 이미 저장된 값이 새 스킴 id와 충돌하지 않는지 확인(현행 4개 id는 그대로 유지되므로 안전) |

## 5) 근거 등급 요약 — 과신 방지

| 주장 | 등급 | 근거 |
|---|---|---|
| 볼륨·노력을 맞추면 세트법 간 근비대 차이가 없다 | **높음** | 메타 3편(Tsartsapakis 2026 g=0.046 p=0.370 · Havers 2026 SMD 0.04 · Sødal 2023 SMD 0.155) + RCT(Angleri 2017) |
| 고급 세트법은 **근력**에는 소폭 유리하다 | **중간** | Tsartsapakis 2026 g = 0.351 [0.170, 0.533] p < 0.001 |
| 드롭세트·마이오렙·레스트포즈가 시간을 1/2~1/3로 줄인다 | **높음** | 메타에 실측 + RCT 2편(35 vs 57분, 세션시간 유의) |
| 드롭세트의 급성 피로 비용이 크다 | **높음** | Havers 2026 — RPE SMD 1.62, 젖산 0.67, 신경근 지표 |
| 실패에서 4~5회 이상 남기면 근비대가 떨어진다 | **높음** | Refalo 2023 메타 + Robinson 2024 메타회귀 |
| 부하–반복 환산표(80% ≈ 8.8회 등) | **높음**(값) / **중간**(적용) | Nuzzo 2023, 269연구·7,289명. **단 개인차 SD ±2.5~4.4회** |
| 세트가 진행되며 반복이 떨어진다(세트2 ≈ 70%) | **높음** | Nuzzo 2024, 29연구 2차분석 |
| 감량폭을 키우면 볼륨이 산다 | **중간** | Helms 2018(2/4/6% → 볼륨 74.6/88.4/114.4) · Khairallah 2009 |
| 워밍업 마지막 단을 무겁게 하면 첫 워킹세트 수행이 좋아진다 | **중간** | 급성 연구 다수 + De Freitas PAP(22회 vs 15회) |
| 그 워밍업 개선이 **근비대로 이어진다** | **없음** | 직접 연구 없음. De Freitas는 세트 2~4에서 이득이 사라졌다 |
| 클러스터가 세트 내 속도·폼을 지킨다 | **중간** | Jukic 2020 메타(속도 유지) — **"폼을 지킨다"는 추론이지 측정된 결과가 아님** |
| 백다운 82.5% 같은 구체 수치 | **낮음** | 부하–반복 표에서 **계산으로 도출**. 직접 검증 실험 없음 |
| 백오프 90%, 드롭 −25%, 피더 90% × 2회 | **낮음(실무)** | 원리는 근거 있으나 정확한 숫자는 임의 |
| 역피라미드(RPT)의 근비대 우위 | **없음** | 미훈련 여성 소규모 연구 1편뿐, 근손상 지표도 함께 상승 |
| GVT 10세트가 5세트보다 낫다 | **반대 근거** | Amirthalingam 2017 — 오히려 5세트가 몸통·팔 제지방에서 우세 |

### 5-B. 이 보고서가 **모르는 것**

1. **탑세트+백오프 vs 스트레이트의 직접 RCT는 여전히 존재하지 않는다.** 1차 보고서 이후 다시 찾았으나 없다. 이 스킴 전체가 간접 논리 위에 서 있다.
2. **백다운 82.5%는 계산값이지 실험값이 아니다.** 부하–반복 표의 개인차(SD ±4.4회 @70%)를 감안하면 사람마다 75~90% 사이 어딘가일 것이다. **첫 2주는 사용자가 실제 반복 수를 보고 조정하도록 안내해야 한다.**
   더 근본적으로, 이 문서의 모든 RIR 추정은 **"탑세트 뒤 피로 계수 ×0.8"** 이라는 가정 위에 있다(§1-0). 이 계수를 직접 측정한 연구는 찾지 못했다. 0.7을 쓰면 권장 배율이 0.85 쪽으로, 0.9를 쓰면 0.80 쪽으로 밀린다 — **결론의 방향은 안 바뀌지만 소수점은 바뀐다.**
3. **"클러스터가 폼을 지킨다"는 속도 유지 데이터에서 끌어온 추론이다.** 요추 부하나 자세 이탈을 직접 측정한 연구는 찾지 못했다.
4. **허리디스크 보유자에게 어떤 세트법이 더 안전한가**에 대한 직접 연구는 없다. 실패 근처 고반복에서 척추 굴곡이 늘어난다는 주장은 모델링·사체 연구 기반이고, 실제 부상률 비교 연구가 없다는 점은 이 앱이 이전 세션에서 이미 확인한 바와 같다.
